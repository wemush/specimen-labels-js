# WOLS cross-library round-trip tests

The conformance vectors only check that an implementation *decrypts* fixtures.
This directory checks the other half: a label *generated* by one library must
decrypt in the other. It covers the WOLS 1.3.0 encrypted URL format with
`kdf=pbkdf2` and `kdf=raw`, and field-level encryption.

| File | Purpose |
| ---- | ------- |
| `matrix.json` | The case matrix (inputs only). ASCII-only, so non-NFC strings can't be renormalized by an editor. |
| `harness.py` | Python side: `generate` a corpus with the installed `wols`, or `verify` a corpus with it. |
| `harness.mjs` | TypeScript side: the same for an installed `@wemush/wols`. |
| `corpus/*-1.3.0.json` | Corpora generated by the published 1.3.0 releases of both libraries. The test suite decrypts them on every run. |

## Where the canonical copy lives

The canonical copy of `matrix.json`, both harnesses, this README and the
corpora is `tests/interop/` in
[wemush/specimen-labels-py](https://github.com/wemush/specimen-labels-py).
[wemush/specimen-labels-js](https://github.com/wemush/specimen-labels-js)
carries a byte-identical copy. Change both in lockstep. The `interop` CI
workflow in each repo warns when its copy differs from the other repo's `main`.

## What the matrix covers

- **Forms:** encrypted URL (`kdf=pbkdf2`, `kdf=raw`) and field-level encryption
  (`kdf=pbkdf2`, `kdf=raw`).
- **Hostile IDs:** the spec example `wemush:Lab A/plate+3%` (which must be
  emitted as `Lab%20A%2Fplate%2B3%25`), `?`, `&`, `=`, `#`, `+` versus space,
  literal `%41`-style text, sub-delims that encoders may leave unescaped,
  JSON-escape characters, control characters, Latin, CJK and supplementary-plane
  characters, and an NFD ID that must not be normalized. Field-level cases put
  the same IDs into the AES-GCM additional data.
- **Passphrases:** NFD and NFC spellings that must derive the same key, U+212B
  (an NFC singleton), Hangul jamo, a ligature that NFC keeps (so an NFKC
  implementation fails), leading and trailing spaces that must not be trimmed,
  and supplementary-plane characters.
- **Iterations:** the minimum (100,000) and the library default (600,000).
- **`sig`:** an optional signature parameter, including one that needs escaping,
  which the decoder must return unchanged.

For every case the verifier checks the generator's output against the 1.3.0
wire rules (path-segment encoding, canonical unpadded base64url, 12-byte IV,
salt of at least 16 bytes, decimal iterations, no `salt`/`i` for `raw`, a fresh
IV per field) and then decrypts it with every listed passphrase. The decrypted
document must equal the matrix input exactly, and `rejectPassphrases` must fail
authentication.

## Running it

From this directory, with both libraries installed:

```bash
# Python -> TypeScript
python harness.py generate matrix.json /tmp/py.json
node harness.mjs verify matrix.json /tmp/py.json

# TypeScript -> Python
node harness.mjs generate matrix.json /tmp/ts.json
python harness.py verify matrix.json /tmp/ts.json
```

`harness.mjs` resolves `@wemush/wols` from its own location, so copy it next to a
`node_modules` that has the package, or set `WOLS_JS_MODULE` to a built entry
point (for example `dist/esm/index.js` of a checkout). `verify` exits non-zero on
any failure.

CI (`.github/workflows/interop.yml`) runs both directions against the other
library's published 1.3.0 package and against its `main` branch.

## Expected failures

`expectedFailures` in `matrix.json` lists known divergences, each with a reason
and a reference, optionally scoped to a `generator` or `decoder` language. A
listed case that passes is reported as `XPASS` and fails the run, so a fixed
divergence has to be removed from the list. Don't delete a failing case.

## Changing the matrix

Edit `matrix.json` in both repos, then regenerate the 1.3.0 corpora with the
published packages (the tests check that each corpus was made from the current
matrix):

```bash
npm install --prefix /tmp/wols-js @wemush/wols@1.3.0 && cp harness.mjs /tmp/wols-js/
node /tmp/wols-js/harness.mjs generate matrix.json corpus/typescript-1.3.0.json
uv venv /tmp/wols-py && uv pip install --python /tmp/wols-py "wols[crypto]==1.3.0"
/tmp/wols-py/bin/python harness.py generate matrix.json corpus/python-1.3.0.json
```

## Adding another implementation

Write a harness with the same `generate` and `verify` commands and corpus format
(`{"corpusVersion": 1, "matrixSha256", "generator": {"implementation",
"language", "version"}, "cases": {"<case id>": {"url"} | {"document"}}}`), then
verify its corpus with both harnesses here and verify both 1.3.0 corpora with it.
